# ТЗ v3 — UX «Слова — тебе на А»

**Цель:** довести игру до состояния «понятно за 10 секунд и ребёнку 6 лет, и родителю»,
не ломая существующую механику и архитектуру. Основано на конкурентном анализе
(матрица функций/UX). Функционально мы уже впереди рынка — работаем над **ясностью
первых секунд, тоном и поводом вернуться**.

> Формат: каждая задача самодостаточна — проблема, что делать (с привязкой к коду),
> критерии приёмки (checkbox), затрагиваемые файлы, оценка. Разработчик берёт задачу
> сверху вниз.

---

## 0. Рамки и правила игры

**Стек как есть:** ванильный JS без сборки, модули `src/*.js` (чистые правила в
`rules.js`/`morph.js`/`stats.js` — DOM не трогают), Telegram Mini App, офлайн через
`sw.js`. Бэкенда нет и не появляется.

**Что НЕ трогаем** (сохранить поведение и тесты):
- Ядро проверки хода `Rules.checkMove` и словарь `Dict.*` — только строки сообщений (см. Задачу 4).
- Логику `syncDerived` / `undo` / `resume` / жизни / задания / «сменить букву».
- Существующие юнит-тесты `tests/rules.test.js` должны остаться зелёными.

**Обязательное для каждой задачи (Definition of Done):**
- Работает на ширине **320px** и на большом экране; ничего не обрезано, нет горизонтального скролла body.
- Корректно в **тёмной и светлой** теме Telegram (тема берётся из `applyTheme`, переменные `--bg/--card/--text/--muted`).
- Тач-таргеты интерактивных элементов **≥ 44×44px**.
- Работает **офлайн** (после первой загрузки) — либо деградирует без ошибок в консоли.
- Тактильный отклик через существующий `buzz('ok'|'warn'|'bad')`, где уместно.
- При изменении ассетов — **поднять версию кеша**: `V` в `src/ui.js` (сейчас `'7'`) и `CACHE` в `sw.js`.

**Приоритеты:** P0 — «три вещи, которых нет ни у кого разом» (ясность + шеринг).
P1 — тон и возвращаемость. P2 — усиления.

# P0 — ясность и вирусность

## Задача 1. Онбординг «живой цепочкой» вместо экрана правил

**Проблема.** Новый игрок не знает механику «на последнюю букву». Экрана правил нет,
но и объяснения нет — родитель вынужден объяснять сам. У конкурентов-эталонов
(Wordle) правило считывается из первого хода.

**Что сделать.**
- Показать **первый-запуск оверлей** поверх экрана старта. Показывается **один раз**;
  флаг хранить через `Storage.set('onboarded', 1)`, проверять в `boot()` после `loadAll`.
- Содержание: три тайла-примера **`Арбуз → Зима → Автобус`** с подсветкой стыковых букв
  (последняя буква слова = первая следующего), затем **пустой тайл `?`** с мигающим
  курсором. Одна строка-подпись: «Следующее слово — на последнюю букву. Телефон
  проверит и запомнит». Одна кнопка **«Играем»** закрывает оверлей.
- Анимация: тайлы появляются по очереди (stagger ~120мс), стыковые буквы «перетекают».
  Уважать `prefers-reduced-motion` — при включённом показывать без анимации.
- Доступ повторно: маленькая ссылка «Как играть» на экране старта (`#setup`), открывает
  тот же оверлей (без записи флага).

**Критерии приёмки.**
- [ ] При самом первом открытии показывается оверлей; после «Играем» — экран старта.
- [ ] При повторном открытии приложения оверлей НЕ появляется автоматически.
- [ ] Ссылка «Как играть» открывает оверлей в любой момент со старта.
- [ ] Подсветка показывает, что `з` в конце «Арбуз» = `з` в начале «Зима» (и т.д.).
- [ ] `prefers-reduced-motion: reduce` → без анимаций, контент сразу на месте.
- [ ] Оверлей перекрывает всё, закрывается только кнопкой; фокус-ловушка для клавиатуры.

**Файлы:** `index.html` (разметка оверлея + CSS), `src/ui.js` (показ/скрытие, флаг),
`src/storage.js` (не менять — используем `get/set`).
**Оценка:** M.

## Задача 2. «Чей ход» — крупно, цветом игрока и буквой-аватаром

**Проблема.** В игре за одним телефоном (pass-and-play) главный провал — забыть, кто
ходит. Сейчас имя выводится строкой `#turnName`, активный игрок — лишь рамкой `.sc.active`.
За столом это не читается.

**Что сделать.**
- В верхней части `#game` добавить **баннер текущего игрока**: фон/акцент — цвет игрока
  из `p.color` (палитра `COLORS`), крупно имя игрока и **огромная нужная буква**
  (переиспользовать/усилить `#letter`, сейчас это `L.textContent`). Буква — доминанта экрана.
- На **смене хода** (в `afterMove` / после `G.turn = nextTurn(...)`): короткий переход
  баннера в цвет нового игрока + `buzz('ok')`. Переход заметный (≥300мс), но не мешает вводу.
- Когда буква не задана — «любое слово» (уже есть ветка в `render`), баннер нейтральный.
- Для режима «тупик» (`G.deadEnd`) и «сменить букву» — баннер отражает актуальную букву
  (логика уже в `render`, нужно только визуально усилить).
- Не ломать автоскролл активного игрока в `#scores` (`scrollIntoView`), но приоритет
  внимания — на баннер, а не на строку очков.

**Критерии приёмки.**
- [ ] Не глядя на очки, за 1 секунду понятно: чей ход (имя+цвет) и на какую букву.
- [ ] При передаче хода баннер меняет цвет на цвет следующего игрока + тактильный отклик.
- [ ] Нужная буква — самый крупный элемент игрового экрана; читается с расстояния вытянутой руки.
- [ ] На 320px имя длиной 14 символов (макс. `maxlength`) не ломает вёрстку.
- [ ] В соло-режиме баннер корректен (один игрок, без «передачи»).

**Файлы:** `index.html` (`#game` шапка + CSS), `src/ui.js` (`render`, `afterMove`).
**Оценка:** M.

## Задача 3. Итоговая картинка-цепочка для шеринга

**Проблема.** Сейчас `share()` отправляет только текст (`shareText` → `switchInlineQuery`).
Визуальный результат (как 🟩-сетка Wordle) расходится по семейным чатам сам — это
наш бесплатный маркетинг вместо рекламы.

**Что сделать.**
- Сгенерировать **картинку итога раунда** на `<canvas>`: вертикальная цепочка тайлов
  сыгранных слов (или топ-N + «…» при длинной партии) с подсветкой стыковых букв,
  заголовок «Слова — тебе на А», победитель/счёт, «злая буква» из `Stats.compute`.
  Стиль — как тайлы онбординга (единый визуальный язык).
- Данные брать из `G.log` (события `type:'word'`) и `Stats.compute(G.players, G.log)`
  (уже используется в `finish`). Цвета игроков — `p.color`.
- Кнопка на экране итогов `#over` (рядом с существующей `#shareBtn`):
  1. **Telegram**: если доступно — поделиться изображением средствами WebApp; при
     невозможности отправить картинкой — фолбэк на текущий текстовый `switchInlineQuery`.
  2. **Сохранить/Скопировать**: `canvas.toBlob` → предложить сохранение картинки
     (и/или копирование), фолбэк — текущее копирование текста в буфер.
- Рендер — **синхронно, локально, без сети** (шрифт — системный/уже загруженный, без внешних CDN — CSP/офлайн).
- Учесть `devicePixelRatio` для чёткости; фикс-ширина карточки (напр. 1080px по длинной стороне).

**Критерии приёмки.**
- [ ] На экране итогов есть действие «Поделиться картинкой»; получается PNG с цепочкой слов и счётом.
- [ ] Картинка читается в тёмном и светлом чате (собственный фон карточки, не прозрачный).
- [ ] Длинная партия (например 40+ слов) не ломает карточку — обрезается до топ-N с «…».
- [ ] Офлайн: картинка генерируется без обращения к сети, без ошибок в консоли.
- [ ] Если платформа не умеет делиться изображением — тихий фолбэк на текстовый шеринг (без ошибки для пользователя).

**Файлы:** `src/ui.js` (`share`, новый рендер — можно вынести в `src/sharecard.js`),
`index.html` (кнопка), `sw.js` (если добавили файл — в кеш + версия).
**Оценка:** L.

# P1 — тон и возвращаемость

## Задача 4. Тон ошибок — воспитательный, не судейский (+ детская вариация)

**Проблема.** Сообщения вроде «Не знаю такого слова» звучат как приговор. Для ребёнка
блок = выход из игры. У нас уже единый тон (`Rules.MSG`, ТЗ §7) — нужно смягчить и
дать детскую вариацию.

**Что сделать.**
- Пересмотреть строки `Rules.MSG` в `src/rules.js` под дружелюбный тон (таблица ниже).
  Менять **только тексты**, не логику веток. Обновить снапшоты в `tests/rules.test.js`,
  если они сверяют точные строки.
- Ввести **детскую вариацию** сообщений: при `CFG.kids` показывать более мягкие/короткие
  формулировки. Реализация без протечки DOM в `rules.js`: `checkMove` возвращает `reason`
  (уже есть) — маппинг `reason → текст` для детского режима держать в `ui.js` (`setMsg`),
  а дефолтные строки оставить в `Rules.MSG`.
- **Никакого красного «WRONG».** Ошибка — янтарный/нейтральный намёк (класс сообщения),
  зелёный `.good` оставить для позитива. `buzz('bad')` для непроходного слова оставить,
  но для «мягких» (overridable) можно `buzz('warn')`.
- Кнопку **«Всё равно засчитать»** (`#overrideBtn`, ветка `overridable`) визуально
  сделать дружелюбной равноправной опцией рядом с «Другое слово», а не мелкой ссылкой.

**Таблица копирайта (черновик, финал — с владельцем продукта):**

| reason | Сейчас | Взрослый тон | Детский тон (`CFG.kids`) |
|---|---|---|---|
| `unknown` | Не знаю такого слова | Не нашёл такого слова — проверим? | Хм, не нашёл такого. Попробуй другое 🙂 |
| `wrong_letter` | Нужно слово на «Х» | Нужно слово на «Х» | Нам нужна буква «Х» |
| `too_short` | Слишком короткое | Слишком короткое слово | Нужно слово подлиннее |
| `repeat` | Это слово уже было | Это слово уже было | Такое уже говорили! |
| `wrong_pos` | Только существительные и прилагательные | Пока берём только существительные и прилагательные | Назови предмет — что это? |
| `wrong_form` | Это форма слова «X». Скажи «X» | Это форма слова «X» — скажи «X» | Скажи «X» |
| `proper_off` | Имена и города выключены в настройках | Имена и города сейчас выключены | (как взрослый) |
| `same_root` | Однокоренное с «X» | Похоже на «X» — однокоренное | Очень похоже на «X» |
| `dead_end` | Тупик — букву меняем | На эту букву слов не осталось — меняем | Слов не осталось — меняем букву |

**Критерии приёмки.**
- [ ] Ни одно сообщение об ошибке не выглядит как «красный запрет».
- [ ] В детском режиме сообщения короче/мягче; вне его — взрослый тон.
- [ ] «Всё равно засчитать» — заметная равноправная кнопка на непроходном слове с `overridable`.
- [ ] `tests/rules.test.js` зелёные (при необходимости обновлены ожидаемые строки).
- [ ] Логика веток `checkMove` не изменена (проверяется тем же тестом).

**Файлы:** `src/rules.js` (строки), `src/ui.js` (`setMsg`, маппинг детского тона, стиль кнопок),
`tests/rules.test.js` (снапшоты строк).

## Задача 5. Две двери с первого экрана вместо меню тумблеров

**Проблема.** Родителю и ребёнку нужны разные сценарии, а старт сразу показывает
тумблеры (жизни, части речи, города, корни, «й», задания, память). Мощно, но пугает
на входе и мешает «сыграть в один тап».

**Что сделать.**
- Вверху `#setup` — **два крупных действия**: **«Играть вдвоём»** (обычный старт,
  дефолтные `CFG`) и **«Для малыша»** (включает `applyKids(true)` и сразу `newGame()`).
- Все существующие тумблеры/чипы (`#limits`, `#hintLimits`, `#livesChips`, `#kidsSw`,
  `#properSw`, `#posSw`, `#rootSw`, `#jSw`, `#tasksSw`, `#memSw`) убрать под
  раскрывающийся блок **«Настройки»** (свёрнут по умолчанию). Внутри — как сейчас.
- Дефолт `startBtn` должен запускать хорошую партию **в один тап** (список игроков уже
  предзаполнен «Игрок 1/2»). Кнопка старта не активна пока `enableStart()` не разрешил
  (словарь) — сохранить это поведение.
- Кнопки «Свои слова» (`#customBtn`) и «История» (`#historyBtn`) оставить доступными,
  но визуально второстепенными.

**Критерии приёмки.**
- [ ] Со старта видны две крупные понятные двери; «Для малыша» запускает детский пресет сразу.
- [ ] Продвинутые настройки скрыты за «Настройки», раскрываются по тапу, состояние сохраняется (`saveCfg`).
- [ ] Обычный игрок может начать партию, не открывая настройки.
- [ ] Все прежние настройки доступны и работают как раньше (регресс не сломан).

**Файлы:** `index.html` (`#setup` разметка + CSS аккордеона), `src/ui.js`
(`renderSetup`, `bind` — новые кнопки, показ/скрытие блока).

## Задача 6. Дневной крючок без бэкенда

**Проблема.** Нет повода открыть завтра. «Одна цель в день» держит возвращаемость даже
без сервера.

**Что сделать.**
- **«Буква дня» / «Задание дня»**: детерминированный выбор из даты (например seed от
  `YYYY-MM-DD`), поэтому одинаков у всех и работает офлайн. Показать плашкой на `#setup`:
  «Сегодня — слова на «Х», сыграно ✓/—».
- **Серия дней (день-стрик)**: считать календарные дни с сыгранной партией. Хранить в
  `Storage` (`{ lastPlayedDate, streakDays }`), обновлять в `finish` при непустом раунде.
  Показать ненавязчиво на старте и в итогах («2 дня подряд 🔥»). Без давления/уведомлений.
- Переиспользовать существующий механизм заданий (`CFG.tasks`, `nextTask`, `TASK_BONUS`)
  как основу, но «задание дня» — отдельная лёгкая сущность на экране старта, не зависит
  от тумблера заданий внутри партии.

**Критерии приёмки.**
- [ ] На старте видно «задание/букву дня»; одинаково для одной и той же даты (детерминизм).
- [ ] Работает офлайн (без запроса к сети).
- [ ] Серия дней растёт при игре в новый день и сбрасывается при пропуске; видна на старте и в итогах.
- [ ] Нет push/назойливых напоминаний; крючок мягкий.

**Файлы:** `src/ui.js` (расчёт seed, показ, обновление в `finish`), `src/storage.js`
(ключи хранения — использовать существующие `get/set`), `index.html` (плашка).

## Задача 7. Озвучка принятого слова (TTS) — для нечитающих

**Проблема.** Против детских эталонов единственная явная дыра — нет озвучки. Для 5–7 лет
это снимает барьер чтения и превращает игру в тренажёр речи.

> Важно: у нас уже есть голосовой **ввод** через `SpeechRecognition` (`startMic`). Здесь
> речь про **вывод** — `window.speechSynthesis` / `SpeechSynthesisUtterance`. Это разные API,
> не путать.

**Что сделать.**
- При принятии слова (`accept`) — если включена озвучка — произнести принятое слово
  (`res.word`) голосом `ru-RU` через `speechSynthesis`. Короткая, отменяемая (`cancel()`
  перед новой), не блокирующая ввод.
- Включение: по умолчанию **включена в детском режиме** (`CFG.kids`), тумблер в
  «Настройки». Хранить в `CFG` (новый флаг, добавить в дефолт и `saveCfg`).
- Деградация: если голоса `ru` нет / API недоступно — молча выключить, не показывать ошибку.
  Проверять доступность (`speechSynthesis.getVoices()`), уважать `visibilitychange`
  (не говорить в фоне; согласовать с `pauseGame`).

**Критерии приёмки.**
- [ ] В детском режиме принятое слово произносится вслух голосом ru (где поддерживается).
- [ ] Тумблер озвучки есть в «Настройки», состояние сохраняется.
- [ ] На устройстве без ru-голоса — тихая деградация, без ошибок и без «немых» задержек ввода.
- [ ] Озвучка не путается с микрофоном (ввод) и не запускается в фоне/на паузе.

**Файлы:** `src/ui.js` (новый флаг в `CFG`, вызов в `accept`, тумблер в `renderSetup`/`bind`).
**Оценка:** S.

# P2 — усиления

## Задача 8. Подсказка как право, а не как поражение

**Проблема.** Подсказка (`hint`, маска) сейчас со штрафом времени (`HINT_PENALTY_MS`) и
может читаться как «сдался». Для ребёнка застревание = выход из игры.

**Что сделать.**
- Оформить кнопку `#hintBtn` дружелюбно — «💡 Подскажи» рядом с вводом, не как штраф-элемент.
- В детском режиме (`CFG.kids`) — без лимита (уже так: `hintLimit = Infinity`) и **без
  штрафа времени** (в детском таймера нет, штраф всё равно не виден, но убедиться, что не копится в `ms`).
- Двухступенчатая маска (`showMask` stage 1 → 2) — оставить, подпись сделать
  подбадривающей («ты почти угадал»).

**Критерии приёмки.**
- [ ] Кнопка подсказки выглядит как помощь, а не как штраф.
