# ТЗ v1 — Локальная версия «Слова — тебе на А» (один телефон)

**Область:** всё, что работает **на одном устройстве, офлайн, без бэкенда** —
pass-and-play за одним телефоном, соло, бот-оппонент, дневной пазл, коллекции.
Это прямое развитие текущей игры на существующем стеке.

> Онлайн-мультиплеер (живой матч двух игроков на разных телефонах, рейтинг,
> матчмейкинг) — **в отдельном ТЗ** `docs/ТЗ-PvP-v2.md` (там появляется бэкенд).
> «Вызов другу по ссылке» (Задача 7) — это асинхронный мостик к PvP, но **без сервера**,
> поэтому живёт здесь.

Формат: проблема → что сделать (с привязкой к коду) → критерии приёмки (checkbox)
→ файлы → оценка (S/M/L). Разработчик берёт сверху вниз. Обоснование — в
`docs/Геймдизайн-план-v1.md`.

# P0 — Фундамент: единый скоринг

## Задача 1. Единая система очков (ядро)

**Проблема.** Три несогласованные валюты: титул победителя = среднее время (`stats.js:65`),
🏆 = число слов (`ui.js:653`), очки заданий 🎯 (`bonus`/`TASK_BONUS`) ни на что не влияют.
Игрок не понимает, за что борется.

**Что сделать.**
- Новый чистый модуль `src/score.js` (без DOM), считает ценность слова и очки хода.
  Формула-черновик (константы в одном месте, тюнятся):
  ```
  score(word) = base + hardBonus + comboBonus + speedBonus + taskBonus
  base       = Σ ценность_букв(word)                       // шкала «Эрудита», Задача 3
  hardBonus  = ценность(финальная_буква), если она «трудная» (value ≥ 5), иначе 0
  comboBonus = round(base * 0.1 * min(currentStreak, 10))  // серия без пасов (G.streak)
  speedBonus = CFG.limit ? round(K * остаток_времени/лимит) : 0   // K≈5
  taskBonus  = задание выполнено ? TASK_BONUS_PTS : 0      // Задача 4
  ```
- В событие хода (`ui.js accept`, объект `ev`) добавить `ev.score` (заменяет `bonus`).
- `stats.js compute` агрегирует `p.score` по игрокам и общий; остаётся без DOM.

**Критерии приёмки.**
- [ ] У каждого слова есть числовая ценность; считается детерминированно.
- [ ] Очки пересчитываются из `log` (после `undo` корректны).
- [ ] `stats.js`/`score.js` — без DOM; юнит-тесты правил зелёные; мини-тест `score.js`.
- [ ] В детском режиме очки можно скрыть/упростить.

**Файлы:** `src/score.js` (новый), `src/stats.js`, `src/ui.js` (`accept`), `index.html`/`sw.js`.
**Оценка:** M.

## Задача 2. Победа по очкам + «номинации»

**Проблема.** Двойной сигнал победителя → за столом непонятно, кто выиграл.

**Что сделать.**
- В `finish()` победитель = больше всех `p.score`. Тай-брейк: больше слов → меньше
  среднее время. Survivor-логика жизней остаётся приоритетной.
- `#overTitle`: «Имя — победа, N очков». Бывшие метрики (среднее, длиннейшее,
  быстрейшее, «злая буква») → **номинации-медальки** в `renderBreakdown` («⚡ Скорострел»,
  «📏 Длинное слово», «🎯 Ловушка»). У каждого игрока хотя бы одна — снижает горечь проигрыша.
- В `render()` показывать текущие очки в `#scores` крупно рядом с числом слов.
- Шеринг (`shareText`/`shareImage`/`ShareCard`) — показывать очки.

**Критерии приёмки.**
- [ ] Победитель по очкам; за 1 сек ясно, кто и с каким счётом.
- [ ] Очки видны в ходе партии; у каждого игрока есть номинация в итогах.
- [ ] Режим с жизнями: победа выжившего сохранена; соло показывает личный счёт.

**Файлы:** `src/ui.js` (`finish`/`render`/`renderBreakdown`/`shareText`), `src/sharecard.js`, `index.html`.
**Оценка:** M.

## Задача 3. Ценность букв «Эрудит» + бонус финальной буквы + превью вживую

**Проблема.** У букв нет ценности → нет стратегии «загнать в угол». Слова не весомы.

**Что сделать.**
- В `src/score.js` — таблица ценности (русский «Скрэббл/Эрудит», ё=е):
  ```
  1: о а е и н т р с в л     2: к м д п у     3: б г ь я
  4: й ы     5: ж з х ц ч     8: ш э ю     10: ф щ ъ
  ```
  Экспорт: `letterValue(ch)`, `wordValue(nk)`, `isHard(ch)`, `HARD_SET`.
- **Бонус финальной буквы (ловушка).** В `accept` финальная буква уже есть
  (`Rules.nextLetter(res.key, CFG.skipJ)`). `isHard` → добавить `hardBonus`. Впервые
  появляется выбор: длинное дорогое слово или короткое на «злую» букву.
- **Превью вживую.** В обработчике `input` поля `#word` (`ui.js:944`) показывать
  набегающую ценность плашкой у поля (пересчёт `score.wordValue`). Дофамин, как в скрэббле.

**Критерии приёмки.**
- [ ] «Съешь» дороже «оса»; слово на «ф/щ» в конце даёт бонус.
- [ ] При наборе видно очки за слово (обновляется на каждый символ).
- [ ] `score.js` — чистый, покрыт мини-тестом; в детском превью можно скрыть.

**Файлы:** `src/score.js`, `src/ui.js` (`accept`, `input`, `render`), `index.html`.
**Оценка:** M.

# P1 — Соло, в которое возвращаются

## Задача 5. Бот-оппонент «Робот» 🤖 (офлайн)

**Проблема.** Соло — эндлесс-тренажёр без противника. Большинство сессий в TG — соло.

**Что сделать.**
- Чистый модуль `src/bot.js`: `pickMove(letter, state, level)` → слово | `null` (пас).
  Офлайн, переиспользует `Dict.freq`/`Dict.pickHint`/`Rules.nextLetter`/`Dict.hasWordsOn`.
- Уровни: **Лёгкий** (частые слова, «думает» 1.5–3 с, иногда пасует), **Средний**
  (реже, средние буквы, 1–2 с), **Сложный** (осознанно заканчивает на трудные буквы —
  ловушка из Задачи 3, редкие слова, ~0.7 с).
- Запуск: «против Робота» на `#setup` (можно отдельной дверью, как «Для малыша»). Бот —
  «игрок» в `G.players` с `bot:true`+уровень, в аватаре помечен 🤖.
- Ход бота идёт через обычный `accept` (те же правила/очки/история). Задержка уровня,
  «Робот думает…», отменяемый таймер; учитывает паузу/`visibilitychange` (не ходит в фоне).

**Критерии приёмки.**
- [ ] Партия 1×бот; бот отвечает валидно на нужную букву, офлайн, не повторяет `G.used`.
- [ ] Три уровня ощутимо различаются; сложный чаще заканчивает на трудные буквы.
- [ ] Ход бота через `accept`; пауза/сворачивание не ломают; нет зависших таймеров.

**Файлы:** `src/bot.js` (новый), `src/ui.js`, `index.html`, `sw.js`/`V`.
**Оценка:** M–L.
